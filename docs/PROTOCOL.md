#### Протокол обмена с платами ПАРН (ATmega128)

**Источники:** прошивки parn1_58.PAS и parn3_58.PAS (Pascal, ATmega128) и низкоуровневый драйвер Unit_com.pas из рабочей программы на Delphi. 

#### 1. Транспорт и адресация

* **Адрес платы:** всегда 1 (в прошивке LANnodeAdr := 1).
* **Схема передачи (эмуляция 9-го бита):** 

  1. Отправка 1 байта адреса (0x01) с чётностью MarkParity.
  2. Пауза 100 мс.
  3. Переключение на SpaceParity и отправка тела команды.

#### 2. Особенности приёма и риски (для проверки на живой плате)

1. **Игнорирование ошибок чётности на приём (DCB.Flags = $1001):** в оригинальной Delphi-программе (Unit_com.pas) бит fParity равен 0 — Windows не отбрасывает байты с «неправильной» чётностью при чтении ответа. 

  * *Риск для Qt:* проверить на реальной плате, не теряет ли QSerialPort байты ответа и не спамит ли ParityError. При необходимости отключать строгую проверку чётности через платформенный API Windows (GetCommState / SetCommState).
2. **Чётность первого байта ответа:** в Delphi-коде формы ПАРН используют функцию Read_parametr (а не Read_master), которая **не** переключает порт обратно на MarkParity перед чтением ответа, а читает все байты на SpaceParity. Подтвердить по логу с платы корректность приёма первого байта.

#### 3. Формат кадра и константы для namespace Protocol

* **RESPONSE_SIZE:** 122 байта.
* **FIELD_SEPARATOR:** '\r' (0x0D).
* **Контрольная сумма (checksum):** сумма байт, 16 бит, порядок **little-endian** (младший байт первым) — подтверждено.
* **Структура модуля (protocol.h/.cpp):** чистые функции в namespace Protocol (не класс), структуры/типы ParseError, ParsedResponse.
